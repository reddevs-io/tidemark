Project Goal

  • Tidemark product brief: Tidemark (applicationId io.reddevs.tidemark, company domain reddevs.io) is an open-source, read-only Android viewer for Health Connect data. It has a dashboard with trends and a record explorer for raw records. License GPL-3.0. Repo github.com/reddevs-io/tidemark. Data never leaves the device: no INTERNET permission, no backend, no sync. English and French from v1. Distribution: GitHub Releases first (Obtainium-friendly), Google Play later under the existing reddevs Organization developer account.
  • v1 data scope: Eight record types, the same in every build: Steps, Distance, ActiveCaloriesBurned, ExerciseSession, SleepSession (with stages), HeartRate, RestingHeartRate, Weight. Read permissions only, plus PERMISSION_READ_HEALTH_DATA_HISTORY when FEATURE_READ_HEALTH_DATA_HISTORY is available.
  • v1 non-goals: Out of scope for v1: writing, editing or deleting data; sync or backend; insights and correlations; widgets and notifications; background reads (no READ_HEALTH_DATA_IN_BACKGROUND); exercise routes; CSV/JSON export (possible later); types beyond the eight v1 types; Play/GitHub flavor split; Room or any local cache.

Overall Architecture

Tech stack: Kotlin + Jetpack Compose. androidx.health.connect:connect-client 1.1.0 stable, which requires compileSdk 36 and AGP 8.9.1 or newer. minSdk 28, compileSdk and targetSdk 36. Vico for charts, with a custom Compose Canvas fallback only for the sleep-stage hypnogram if Vico doesn't fit. Material 3 with dynamic color and dark theme. Navigation-Compose. ViewModels exposing StateFlow. Manual DI through an AppContainer, no Hilt. Unit tests with androidx.health.connect:connect-testing (FakeHealthConnectClient) on Robolectric.
Module and package layout: Single app module. Packages: data (one HealthRepository interface plus HealthConnectHealthRepository wrapping HealthConnectClient, and domain models), dashboard, explorer, onboarding, settings. The plan adds three small supporting packages: ui (theme and shared components), navigation (routes and NavHost) and format (locale-aware unit, number and date formatting). Data access is live queries only, no Room or cache.
CI, signing and release: GitHub Actions runs lint and unit tests on every PR. A tag push builds a signed APK attached to a GitHub Release plus an AAB for Play. Keystore and passwords live in encrypted GitHub secrets with an offline backup of the keystore. Same applicationId and same signing key on GitHub and Play so users can move between channels; versionCodes must be monotonic across channels. Upload our own key to Play App Signing instead of letting Google generate one.

Dashboard — Tiles for steps, active calories, distance, last night's sleep with stages, resting heart rate and latest weight, each with a sparkline. A tile opens a detail chart with day/week/month/year ranges. The chart drills down to that day's records in the explorer. Charts use Health Connect aggregates (aggregate, aggregateGroupByPeriod, aggregateGroupByDuration for the day view), which deduplicate by the user's data-source priority in Health Connect settings. No per-metric source picker.

2026-11-19T09:51:48.367179Z

Record explorer — Pages through raw records by type with readRecords and page tokens. Shows every field plus metadata, including dataOrigin (which app wrote the record), with a filter by source. One generic field-dump renderer fed by a per-type field extractor, not a bespoke screen per type. Explorer coverage equals the eight v1 types.

2026-11-19T09:51:48.371542Z

Onboarding and privacy rationale — Checks Health Connect availability with getSdkStatus. On Android 9-13 Health Connect is a separate Play app: manifest needs a <queries> entry for com.google.android.apps.healthdata and the app shows an install prompt. Runs the permission request flow and handles partial grants. Required rationale handling, without which the permission dialog won't show: an activity for androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE (Android 13 and below) and an activity-alias for android.intent.action.VIEW_PERMISSION_USAGE with category android.intent.category.HEALTH_PERMISSIONS, protected by android.permission.START_VIEW_PERMISSION_USAGE (Android 14+). Both show the bundled in-app privacy policy.

2026-11-19T09:51:48.376154Z

Play Health apps requirements (research) — Play listing needs: the Health apps declaration with a justification for each data type in EN and FR; a Data safety form; a privacy policy URL that matches the in-app rationale; every permission tied to a visible feature (Play denies bulk permission lists when not necessary); history permission justified as view your past records. Review time is undocumented, unofficially 1-2 weeks, and any change to the type set means re-declaring. Other connect-client apps ship on F-Droid, possibly with a NonFreeDep anti-feature on Android 13 and below.

2026-11-19T09:51:48.433278Z

Reference apps (research) — Heartwood (GPL-3.0) covers the history-permission flow, paged reads and Robolectric + connect-testing tests, but has no range switcher, sleep stages, raw explorer with data origin or Play listing. Health Disconnect (Apache-2.0) is the closest existing raw explorer; Apache-2.0 code can be used in a GPL-3.0 project with attribution.
