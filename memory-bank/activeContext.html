Recent Changes

  • Fixed release signing reading null key alias and password: In app/build.gradle.kts, bare keyAlias and keyPassword inside create("release") resolved to the signing config own null properties, so signed builds failed in validateSigningRelease. Found by T-008, fixed in the primary session by prefixing the script vals with release. A throwaway-key signed assembleRelease now passes apksigner verify and the permission check.
  • T-010 integration cleanups: One data.HealthConnectIntents helper (installOrUpdate, access = manage-data intent then HealthConnectClient.ACTION_HEALTH_CONNECT_SETTINGS, openAccess, startFirst) replaces the onboarding, settings, dashboard and explorer copies; no HealthConnectClient outside data. Detail permission error gains an Open Health Connect settings button. AppLabels moved to ui/components and shared by dashboard, detail and explorer. Explorer queries sleep sessions noon to noon so a sleep drill-down for a morning finds the night before. AppContainer passes its clock to the formatter. Added NOTICE and .markdownlint.jsonc (MD013 off). 276 tests pass.
  • Device fixes from the API 36 and API 28 checklist: On Android 9 to 13 getSdkStatus reports UPDATE_REQUIRED when Health Connect is missing but installable, so availability() now checks whether the provider package is installed and returns NOT_INSTALLED when it is not (onboarding showed Update instead of Install). Open Health Connect settings now goes to Health Connect home first (App permissions is one tap away; third-party apps cannot open their own permission page), with the manage-data screen as fallback; the manage-data screen alone was a dead end for granting access.
  • Large-text layout fixes from the device checklist: At 200% font the tile and banner TextButtons (pill shape) clipped wrapped text at their corners; they now use MaterialTheme.shapes.small. Top app bars keep 64 dp and the title overflowed into the status bar; every TopAppBar now passes expandedHeight = scaledTopAppBarHeight() (ui/components), which grows with the font scale.

Open Questions / Issues

  • No API 28 emulator image installed: T-001 verified launch only on a new API 36 AVD (tidemark-api36, google_apis). There is no API 28 system image locally, and checking Health Connect on Android 9 needs a Google Play image (about 1 GB). T-010 must install system-images;android-28;google_apis_playstore;x86_64 or use a real device.
  • Developer name and tagline unconfirmed: The privacy policy names the developer as RedDevs pending the user confirming the legal name. Short descriptions ship EN 1 / FR 1; EN 2 and FR 2 are recorded as alternatives in the T-009 report.
  • Duplicate Health Connect settings helpers: T-002 (data/HealthConnectIntents), T-003 (onboarding/HealthConnectIntents), T-004 (settings/SettingsLinks) and T-007 (explorer/HealthConnectSettings) each wrote a way to open Health Connect settings. T-010 consolidates them into one helper and verifies the per-app screen on device (checklist item 3).
  • App label lookup duplicated: Dashboard (T-005) and explorer (T-007 AppLabels) each resolve app labels; T-010 may move one helper to ui/components.
  • Explorer day filter for sleep drill-down: Sleep drill-down passes the morning date; T-010 checks that the explorer finds sessions overlapping that day (night started the evening before).
  • Known cosmetic and design points after T-010: The resting heart rate reference line runs through its own label in the day view. The sleep tile shows time in bed (start to end) while charts show Health Connect sleep duration, which excludes awake stages. TalkBack itself was not run (not on the emulator images); content descriptions were checked. Checklist item 2 (outdated Health Connect) is N/A on both API levels.
