Build Tidemark instead of contributing to an existing app

RationaleHeartwood lacks a range switcher, sleep stages, a raw explorer with data origin and a Play listing. Both projects are GPL-3.0, so code borrowed from Heartwood is allowed with attribution.
Implementation DetailsThe user chose to build their own app. Heartwood (github.com/GuyOnWifi/heartwood, GPL-3.0, Kotlin/Compose, connect-client 1.1.0, Canvas charts, Robolectric + connect-testing tests, minSdk 28) is the reference for the history-permission flow, paged reads and tests. Health Disconnect (github.com/Monkopedia/health-disconnect, Apache-2.0) is the closest existing explorer.
2026-11-19T09:51:48.390017Z

License GPL-3.0

RationaleMatches Heartwood so its code can be reused with attribution. Whether source headers say GPL-3.0-only or GPL-3.0-or-later is still open.
Implementation DetailsTidemark is licensed GPL-3.0 (LICENSE already in repo).
2026-11-19T09:51:48.392772Z

No network, on-device only

RationalePrivacy is the product's core promise and it keeps the Play Data safety form trivial: nothing collected, nothing shared.
Implementation DetailsThe manifest declares no INTERNET permission. No backend, no sync, no analytics, no crash reporting service. Export to CSV/JSON is a later nice-to-have.
2026-11-19T09:51:48.395462Z

Same eight record types in every build, no flavor split

RationalePlay denies bulk permission lists that aren't tied to a visible feature, and any change to the type set means re-declaring. One type set keeps one manifest, one declaration and one signing story.
Implementation DetailsExplorer coverage equals the v1 types. An explorer covering all ~40 Health Connect types and a Play/GitHub flavor split were both rejected.
2026-11-19T09:51:48.398079Z

History permission with 30-day fallback

RationaleWithout the history permission Health Connect silently omits older data from results, so the UI must tell the user why older data is missing. Play justification: view your past records.
Implementation DetailsRequest PERMISSION_READ_HEALTH_DATA_HISTORY only when getFeatureStatus(FEATURE_READ_HEALTH_DATA_HISTORY) returns available. Where it is unavailable or denied, show a banner and fall back to the default window, which is 30 days before the first permission grant.
2026-11-19T09:51:48.401226Z

Aggregates for charts, no source picker

RationaleAggregates deduplicate by the data-source priority the user already set in Health Connect settings, so the dashboard avoids double counting when several apps write the same metric. A per-metric picker would duplicate that setting.
Implementation DetailsDashboard charts use aggregate, aggregateGroupByPeriod and aggregateGroupByDuration. The explorer shows per-record dataOrigin with a filter by source.
2026-11-19T09:51:48.405011Z

Live queries, no local cache

RationaleLess code and no second copy of health data on disk. Revisit only if year charts prove slow on a real device.
Implementation DetailsEvery screen reads Health Connect directly. No Room database or cache in v1.
2026-11-19T09:51:48.408646Z

Vico for charts

RationaleVico is a maintained Compose-native chart library, which avoids hand-drawing axes, scrolling and markers. A hypnogram is a stepped range chart that may not map to Vico's model.
Implementation DetailsUse Vico (compose-m3) for sparklines and detail charts. Fall back to a custom Compose Canvas only for the sleep-stage hypnogram if Vico doesn't fit.
2026-11-19T09:51:48.412848Z

Manual DI, single module

RationaleThe app is small. Manual DI keeps the build fast and the wiring readable for contributors.
Implementation DetailsOne app module and an AppContainer created in the Application class. No Hilt, no multi-module split.
2026-11-19T09:51:48.416456Z

Distribution order and signing

RationaleAn Organization account sidesteps the 12-tester / 14-day closed-test rule for personal accounts. A shared key lets users update across channels.
Implementation DetailsGitHub Releases first, Google Play later once the permission set is stable, under the reddevs Organization developer account. F-Droid and IzzyOnDroid are possible later but not chosen. One key and one applicationId across channels; our own key uploaded to Play App Signing.
2026-11-19T09:51:48.419713Z

Privacy policy as PRIVACY.md in EN and FR

RationalePlay requires a privacy policy URL that matches what the in-app rationale shows. One source file for both keeps them in sync.
Implementation DetailsPRIVACY.md and its French version live at the repo root, are published via GitHub Pages, and are bundled into the app for the rationale screen. Short and honest: no collection, no network, on-device only.
2026-11-19T09:57:58.542875Z

Frozen contracts and compiling stubs from T-001

RationaleA single-module app has many shared files. Freezing them up front lets eight agents work in parallel without merge conflicts.
Implementation DetailsT-001 writes HealthRepository, domain models, MeasurementFormatter, UserPreferences, Routes, AppContainer and a compiling stub for every Wave 1 class. Wave 1 agents may not change those signatures; changes go through the plan's blocker process.
2026-11-19T09:57:58.545661Z

One strings file per feature

RationaleAndroid merges every file in values/, so parallel workstreams never edit the same XML.
Implementation DetailsEach feature owns values/strings_<feature>.xml and values-fr/strings_<feature>.xml; T-001 owns strings_common.xml.
2026-11-19T09:57:58.548236Z

Wave 1 agents run in separate worktrees

RationaleWith one module, a half-written file in one stream breaks every other stream's compile, and parallel Gradle runs contend for the same build locks.
Implementation DetailsEach Wave 1 child uses isolation worktree from the committed Wave 0 base. Children never commit; the primary session copies each workstream's owned paths back and verifies the merged tree.
2026-11-19T09:57:58.553148Z

Unit system resolution

RationaleMatches what people in those regions expect without a per-unit settings matrix.
Implementation DetailsLocaleData.getMeasurementSystem picks the default: US gets miles and pounds, UK miles and kilograms, everyone else metric. The override switches metric or imperial as a whole. Energy is always kcal. No stones in v1.
2026-11-19T09:57:58.556540Z

Chart bucket rules

RationaleKeeps each chart to one aggregate call and attributes overnight sleep to a single morning.
Implementation DetailsDay range: hourly buckets via aggregateGroupByDuration. Week and month: daily buckets; year: monthly buckets via aggregateGroupByPeriod. Year view of cumulative metrics shows the daily average per month over days with data. Weeks start per WeekFields.of(locale). Sleep buckets run noon to noon.
2026-11-19T09:57:58.559369Z

Last-night sleep selection

RationalereadRecords does not apply the Health Connect priority order, so the app needs a deterministic rule.
Implementation DetailsLast night is the longest SleepSession ending between 12:00 yesterday and now. With overlapping sessions from several apps, the tile shows the longest and names its source.

HeartRate visible in the resting HR day view

RationalePlay requires every requested type to back a visible feature. This ties HeartRate to the dashboard as well as the explorer.
Implementation DetailsThe resting heart rate detail day view plots that day's HeartRate samples with the resting value as a reference line. ExerciseSession is visible through the explorer.

Series summary statistics

RationaleAveraging over days with data needs daily buckets.
Implementation DetailsCumulative metrics: total is the window sum, average is per bucket with data (hour in day view, day otherwise), min and max over displayed points. Health Connect error mapping

RationaleOne failed metric must not break the others.
Implementation DetailsRate limits map to RateLimited (platform error code on API 34+, message match on 28 to 33); RemoteException and IOException to Unavailable; SecurityException to PermissionMissing(type); everything else to Unexpected. readRecord treats IllegalArgumentException (unknown id) as null. Sleep tie-break: longest, then later end, then package name, then id.
