Tidemark v1 implementation plan

Created 2026-11-19 · Status proposed · Repo reddevs-io/tidemark · Memory Bank session 1ddffc95-64fb-4951-b127-caecca016c52

Goal. Ship Tidemark v1: a read-only Android viewer for Health Connect with a trend dashboard and a raw record explorer, in English and French, with no network access. Release it as a signed APK on GitHub Releases, then submit to Google Play.

Source of truth. The agreed design lives in the Memory Bank (structural goal, feature and architecture entries plus the decision log). This plan adds the build order, the contracts that let work run in parallel, and acceptance criteria. Where this plan makes a choice the design left open, it says so and the choice is recorded as a decision.

Not in this plan. Everything listed under v1 non-goals in the bank: writes, sync, insights, widgets, notifications, background reads, export, exercise routes, more record types, flavors, local cache.

3. Choices this plan makes

The design left these open. Each is recorded in the decision log so later sessions don't re-argue them.

  1. Frozen contracts and stubs. T-001 writes the repository interface, domain models, formatter and preferences interfaces, routes, AppContainer, and a compiling stub for every class a later workstream fills in. Wave 1 agents may not change those signatures. This removes merge conflicts in a single-module app.
  2. One strings file per feature. values/strings_<feature>.xml and values-fr/strings_<feature>.xml. Android merges every file in values/, so parallel workstreams never edit the same XML file.
  3. Worktree per Wave 1 agent. One module means one agent's half-written file breaks every other agent's compile, and parallel Gradle runs fight over the same build/ locks. Each Wave 1 agent runs with isolation: "worktree" and the primary session copies the owned paths back.
  4. Domain models carry SI values. Meters, kilocalories, kilograms, beats per minute, step counts, Instant and Duration. Only the format package converts for display.
  5. Units by measurement system. android.icu.util.LocaleData.getMeasurementSystem (API 28) picks the default. US gets miles and pounds, UK gets miles and kilograms, everyone else is metric. The settings override switches metric or imperial as a whole. Energy is always kcal. Stones are not supported in v1.
  6. Chart buckets. Day range shows hourly buckets (aggregateGroupByDuration). Week and month show daily buckets and year shows monthly buckets (aggregateGroupByPeriod). The year view of cumulative metrics (steps, calories, distance, sleep) shows the daily average for each month, and averages are taken over days that have data. Weeks start on the locale's first day (WeekFields.of(locale)).
  7. Sleep belongs to the morning it ends. Sleep buckets run noon to noon, so a night that crosses midnight lands in one bucket. "Last night" is the longest session ending between 12:00 yesterday and now. If several apps wrote overlapping sessions, the tile shows the longest one and names its source.
  8. The resting heart rate detail day view plots that day's HeartRate samples with the resting value as a reference line. That gives the HeartRate permission a visible dashboard use, which helps the Play declaration. ExerciseSession is visible through the explorer.
  9. Source list in the explorer is the union of AggregationResult.dataOrigins for the range and every dataOrigin seen in loaded pages, because aggregates may leave out lower-priority sources.
  10. App labels for data origins. The manifest adds a <queries> intent entry for androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE. Every Health Connect app must declare that intent, so their labels and icons become visible to Tidemark without QUERY_ALL_PACKAGES. If a label can't be resolved, show the package name.
  11. Manual paging, no Paging 3. The explorer loads 100 records per page and fetches the next page when the list nears its end.
  12. Local preferences in DataStore. Two values only: the unit override and the time Tidemark first saw a granted permission. The second value dates the 30-day banner ("data from about 20 October onwards").
  13. Privacy policy has one source. PRIVACY.md and PRIVACY.fr.md at the repo root. A Gradle copy task in app/build.gradle.kts bundles them as assets, and a Pages workflow publishes them at https://tidemark.reddevs.io/privacy/ and /fr/privacy/. The app renders headings, paragraphs and bullet lists with a small built-in renderer.
  14. Versioning. gradle.properties holds tidemark.versionName and tidemark.versionCode. A person bumps them by hand, and the release workflow fails if the tag does not equal v + versionName or the code did not increase. One integer sequence covers both channels.
  15. Belt and braces on network. The manifest removes INTERNET with tools:node="remove", and CI fails if the merged release manifest or the built APK lists INTERNET or ACCESS_NETWORK_STATE.
  16. No backup. android:allowBackup="false". Tidemark stores no health data, and there is nothing worth restoring.
  17. License GPL-3.0-or-later with SPDX headers. Every Kotlin, Gradle and workflow file starts with SPDX-License-Identifier: GPL-3.0-or-later. Heartwood is GPL-3.0-or-later too, so borrowed files keep the same terms, and Apache-2.0 code from Health Disconnect can be combined with it. Files copied from either project keep their original copyright line next to ours.
  18. Custom domain for the privacy policy. GitHub Pages serves tidemark.reddevs.io. Play's privacy URL is https://tidemark.reddevs.io/privacy/.
  19. Store text in fastlane layout. fastlane/metadata/android/{en-US,fr-FR}/. Obtainium, F-Droid and IzzyOnDroid all read this layout, and it doubles as the source for the Play listing.

4. Shared contracts (frozen after T-001)

Signatures are a sketch. T-001 may adjust names to compile, but once T-001 is accepted these files change only through the blocker process in section 7.

As built by T-001 (2026-11-19). These facts override the sketch below.

  • Toolchain. AGP 9.5.1 (built-in Kotlin, no kotlin-android plugin), Kotlin 2.4.21, Gradle 9.9.1, Compose BOM 2026.09.00, Navigation 2.10.2, Vico 3.3.1, DataStore 1.3.0, Robolectric 4.18.1. Versions live in gradle/libs.versions.toml.
  • compileSdk is 37, and targetSdk stays 36. Compose 1.12, Navigation 2.10 and Vico 3.3 refuse to build against 36. compileSdk only changes the build, not runtime behaviour.
  • connect-testing is pinned to 1.0.0-alpha03. alpha04 pins connect-client 1.2.0-alpha05.
  • Robolectric runs at SDK 34 (app/src/test/resources/robolectric.properties), because it needs JDK 21 for SDK 35 and above and the toolchain is JDK 17. Don't override it per test with @Config(sdk = 35+).
  • Test records. The public Metadata constructor can't set an id or data origin, and IntervalRecord and InstantaneousRecord are internal. Use TestRecords.metadata(id, packageName) (it wraps connect-testing's Metadata.populatedWithTestValues) and FakeHealthRepository.timeOf(record).
  • Aggregates in FakeHealthConnectClient (risk R1, now confirmed): the fake does not compute them. Stub results through fake.overrides.aggregate, aggregateGroupByPeriod and aggregateGroupByDuration, using connect-testing's AggregationResult(dataOrigins, metrics) factory.
  • Permission allow-list. The APK also requests io.reddevs.tidemark.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION, an app-private signature permission that androidx.core adds. T-008's permission check must allow it. ManifestContractTest already does.
  • Navigation enums (RecordType, Metric, ChartRange) carry @Keep so R8 keeps their serializers.
  • Signature differences from the sketch.
    • AppContainer(context, healthRepository = ..., userPreferences = ..., clock = Clock.systemDefaultZone(), scope = ...). Tests pass fakes and backgroundScope. Use container.clock for "today".
    • MeasurementFormatter also has val locale and metricValue(metric, value). DateStyle is SHORT, MEDIUM, LONG or DAY_MONTH. The implementation constructor is LocaleMeasurementFormatter(context, locale, unitPreference).
    • The Explorer route stores typeName: String? and dayEpochDay: Long?, with computed type and day, and a factory Explorer.of(type, day, sourcePackage).
    • RecordType.readPermissions and RecordType.fromRecord(record) are companion helpers.
    • ErrorState(modifier, message, onRetry), EmptyState(message) and LoadingState() are in ui/components, along with PlaceholderScreen (used by the stubs) and Modifier.semanticsLabel().
    • Shared test fixtures are in $TEST/testing: FakeHealthRepository (with failures and calls maps keyed by Call, and it enforces read permissions), FakeUserPreferences, MainDispatcherRule and TestRecords.
  • Health Connect in French is called "Connexion Santé". Use that name in every French string.

    fun permissionsToRequest(includeHistory: Boolean): Set<String>
    suspend fun grantedPermissions(): Set<String>
    suspend fun historyAccess(): HistoryAccess

    suspend fun todayTotal(metric: Metric, today: LocalDate): Double?   // steps, calories, distance
    suspend fun series(metric: Metric, window: ChartWindow): Series
    suspend fun lastNightSleep(now: ZonedDateTime): SleepNight?
    suspend fun sleepNight(morning: LocalDate): SleepNight?
    suspend fun latest(metric: Metric): LatestValue?                    // weight, resting HR
    suspend fun heartRateSamples(day: LocalDate): List<HeartRateSample>

    suspend fun dataOrigins(type: RecordType, start: Instant, end: Instant): Set<DataSource>
    suspend fun readPage(type: RecordType, start: Instant, end: Instant, source: DataSource?,
                         pageToken: String?, pageSize: Int = 100): RecordPage
    suspend fun readRecord(type: RecordType, id: String): Record?
}

HealthAccessException is a sealed class with PermissionMissing(type), RateLimited, Unavailable and Unexpected(cause). The repository maps SecurityException, RemoteException, IOException and IllegalStateException to it. ViewModels catch it and expose an error state. They never let it crash the app.

Other frozen files

  • settings/UserPreferences.kt: unitPreference: Flow<UnitPreference> (SYSTEM, METRIC, IMPERIAL), suspend setUnitPreference(), firstGrantAt: Flow<Instant?>, suspend recordFirstGrantIfAbsent(Instant).
  • format/MeasurementFormatter.kt: steps(Long), distance(meters), energy(kcal), mass(kg), heartRate(bpm), duration(Duration), date(LocalDate, DateStyle), time(Instant), dateTime(Instant), rangeLabel(ChartWindow), distanceUnitLabel(), massUnitLabel(), plus toDisplayDistance(meters) and toDisplayMass(kg) for chart axes. AppContainer exposes formatter: StateFlow<MeasurementFormatter>, rebuilt when the locale or unit preference changes.
  • navigation/Routes.kt: type-safe Navigation-Compose routes with kotlinx.serialization: Onboarding, Dashboard, MetricDetail(metric, range, anchorEpochDay), Explorer(type?, dayEpochDay?, sourcePackage?), RecordDetail(type, recordId), Settings, PrivacyPolicy.
  • Route composable stubs, one per feature, each taking AppContainer plus navigation callbacks: OnboardingRoute(onDone), DashboardRoute(onOpenMetric, onOpenExplorer, onOpenSettings), MetricDetailRoute(args, onOpenRecords, onBack), ExplorerRoute(args, onOpenRecord, onBack), RecordDetailRoute(args, onBack), SettingsRoute(onOpenPrivacy, onBack), PrivacyPolicyScreen(onBack). 5. Workstream prompts

Each prompt is self-contained. The primary session pastes it into the Agent call as is, with subagent_type set to the listed agent and isolation: "worktree" for Wave 1. Every prompt implicitly includes the common rules block below.

Common rules for every child agent

  • Project: Tidemark, a read-only, offline Android viewer for Health Connect. Kotlin, Jetpack Compose, Material 3, connect-client 1.1.0, minSdk 28, compileSdk and targetSdk 36, single app module, manual DI through AppContainer, ViewModels with StateFlow. License GPL-3.0-or-later: start every new Kotlin, Gradle and workflow file with an SPDX-License-Identifier: GPL-3.0-or-later comment. Privacy policy URL: https://tidemark.reddevs.io/privacy/.
  • Memory Bank: run mbctl start --mode code --topic "<task id and title>" and use mbctl search for decisions. Do not run mbctl append. Put suggested events in your report instead, and the primary session records them.
  • Git: do not stage, commit, push, reset, rebase, merge, tag or switch branches. Leave changes in your worktree.
  • Edit only your exclusive owned paths. Read anything. If you need a change to a frozen contract or to another workstream's file, stop that part and report it as a blocker with the exact proposed diff.
  • No INTERNET or network-state permission, no network libraries, no analytics. Never request write permissions or READ_HEALTH_DATA_IN_BACKGROUND.
  • Every user-facing string goes in your own strings_<feature>.xml with a French translation in values-fr/. Keep "Tidemark" untranslated. Use the formatter for numbers, units and dates.
  • Code borrowed from Heartwood (GPL-3.0) or Health Disconnect (Apache-2.0) is allowed. Report the repo, file path, commit and what you took, so T-010 can write NOTICE.
  • Before reporting, run ./gradlew lintDebug testDebugUnitTest in your worktree and include the result.
  • Report: changed and new files; tests added and their result; acceptance criteria with pass or fail each; deviations and why; borrowed code; blockers; suggested Memory Bank events (task status for your task ID, decisions, patterns).

T-002 · Data layer (Wave 1, mb-code, worktree)

Goal. Implement HealthConnectHealthRepository against the frozen HealthRepository interface. Heartwood is the reference for the history permission flow and paged reads.

  • Availability: HealthConnectClient.getSdkStatus(context, "com.google.android.apps.healthdata") maps to HcAvailability. Create the client lazily, and only when the status is available.
  • History: client.features.getFeatureStatus(HealthConnectFeatures.FEATURE_READ_HEALTH_DATA_HISTORY). permissionsToRequest(includeHistory) adds the history permission only when asked and available. historyAccess() returns UNAVAILABLE, NOT_GRANTED or GRANTED.
  • Totals and series use aggregate, aggregateGroupByPeriod (day, week, month and year buckets, with LocalDateTime boundaries in the device zone) and aggregateGroupByDuration (hourly day view). Metrics map as follows: steps COUNT_TOTAL, active calories ACTIVE_CALORIES_TOTAL, distance DISTANCE_TOTAL, sleep SLEEP_DURATION_TOTAL with noon-to-noon buckets, resting HR BPM_AVG/BPM_MIN/BPM_MAX, weight WEIGHT_AVG/WEIGHT_MIN/WEIGHT_MAX. Follow the bucketing and year-average rules in section 3.
  • Sleep: lastNightSleep and sleepNight read SleepSessionRecord through readRecords and pick per the rule in section 3. Map stage constants to SleepStage.
  • latest() reads with ascendingOrder = false and pageSize = 1 over the last 365 days.
  • heartRateSamples(day) flattens HeartRateRecord.samples for the local day, paging through all results.
  • readPage and readRecord wrap readRecords and readRecord, passing the page token and a dataOriginFilter when a source is given. dataOrigins uses each type's aggregate metric and returns AggregationResult.dataOrigins.
  • Map exceptions to HealthAccessException. A missing read permission for one metric must not fail the others.

Acceptance criteria.

  1. Robolectric tests with FakeHealthConnectClient cover: paging across at least three pages with a token; the source filter; readRecord found and missing; last-night selection with two overlapping sessions from different sources; stage mapping; history access in its three states; a missing permission turning into PermissionMissing.
  2. Aggregation tests cover bucket boundaries for each range, including a DST change week in Europe/Paris, a locale whose week starts on Sunday (en-US) and one on Monday (fr-FR), noon-to-noon sleep buckets, and year averages over days with data. If the fake client can't aggregate, stub aggregation results through its overrides, or move bucket math into pure functions and test those. Say which approach you used.
  3. No class outside data references HealthConnectClient.
  4. Common rules lint and test command passes.
T-003 · Onboarding, permissions and privacy rationale (Wave 1, mb-code, worktree)

Goal. The first-run flow, permission handling and the privacy policy screens that Health Connect requires.

  • OnboardingGate.startDestination returns Dashboard when Health Connect is available and at least one read permission is granted, and Onboarding otherwise.
  • The onboarding screens. First, a welcome screen saying what Tidemark does and that data stays on the device. Then a Health Connect status step. If Health Connect is not installed, an install button opens market://details?id=com.google.android.apps.healthdata&url=healthconnect%3A%2F%2Fonboarding, with a fallback to the Play web URL in a browser intent. If an update is required, show an update prompt. Unsupported devices get an explanation and nothing else. Re-check the status on resume.
  • Permission step: launch PermissionController.createRequestPermissionResultContract() with repository.permissionsToRequest(includeHistory = repository.historyFeatureAvailable()). If at least one read permission comes back, call recordFirstGrantIfAbsent(now) and finish. If none come back, explain and offer a retry plus a button to Health Connect's settings for Tidemark, because the system stops showing the dialog after repeated denials.
  • PrivacyPolicyScreen and PrivacyPolicyActivity render the bundled PRIVACY.fr.md when the app locale is French and PRIVACY.md otherwise, through a small Markdown renderer that handles headings, paragraphs, bullet lists, bold and links. The activity serves both the rationale intent and the Android 14+ alias, and it works when launched cold by Health Connect without going through MainActivity.
  • A test should prove the manifest declares exactly what the rationale contract needs, with the activity resolving both intents under Robolectric.

Acceptance criteria.

  1. ViewModel tests with FakeHealthRepository cover: not installed, update required, all granted, partial grant, none granted, and history unavailable (history permission not requested).
  2. A Robolectric test resolves ACTION_SHOW_PERMISSIONS_RATIONALE and VIEW_PERMISSION_USAGE with category HEALTH_PERMISSIONS to Tidemark's component.
  3. The Markdown renderer has unit tests for each supported element and falls back to plain text for anything else.
  4. All strings are in EN and FR.
  5. Common rules lint and test command passes.
T-004 · Settings, units and formatting (Wave 1, mb-code, worktree)

Goal. Locale-aware formatting, the unit override, and the settings screen.

T-008 · CI and release pipeline (Wave 1, mb-code, worktree)

Goal. GitHub Actions for PRs, tagged releases and the privacy policy site.

  • .github/workflows/ci.yml runs on pull requests and pushes to main. It does Gradle wrapper validation, JDK 17 (or the JDK the AGP version requires), Gradle cache, ./gradlew lintDebug testDebugUnitTest assembleRelease, then a permission check script that fails if the release APK requests any permission outside the allowed list (the nine Health Connect read permissions). It uploads lint and test reports as artifacts. Pin third-party actions to commit SHAs.
  • .github/workflows/release.yml runs on tags v*. It checks that the tag equals v + tidemark.versionName and that versionCode is greater than the previous release's code (read from the latest release asset or a versionCode file attached to it). It decodes the keystore from the TIDEMARK_KEYSTORE_B64 secret into the runner temp dir, sets the four signing env vars from secrets, builds assembleRelease bundleRelease, verifies the APK with apksigner verify --print-certs, and writes SHA256SUMS. Then it creates a GitHub Release with the APK named tidemark-<version>.apk, the AAB and the checksums. The release notes come from fastlane/metadata/android/en-US/changelogs/<versionCode>.txt. Tags containing -rc are marked as pre-releases.
  • .github/workflows/pages.yml publishes PRIVACY.md at /privacy/ and PRIVACY.fr.md at /fr/privacy/, plus a minimal index, through actions/deploy-pages, whenever those files change on main. The site uses the custom domain tidemark.reddevs.io with HTTPS enforced. docs/release.md lists the one-time setup the user does: a DNS CNAME record from tidemark to reddevs-io.github.io, verifying reddevs.io in the GitHub organization's Pages settings (this blocks domain takeover), and setting the custom domain on the repo.
  • scripts/check-permissions.sh holds the permission check, so it also runs locally.
  • docs/release.md is the runbook: generating the upload/app key with keytool (RSA 4096, long validity), making the offline backup (two copies on separate encrypted media, passwords in the password manager, no copy in the repo), base64-encoding it into the secrets, bumping versions, tagging, verifying the release, and later uploading the same key to Play App Signing with PEPK.

Acceptance criteria.

  1. actionlint passes on all workflows.
  2. The permission script passes on the T-001 release APK and fails on an APK built with INTERNET added (show both runs).
  3. A dry run of the release steps with a throwaway keystore (local, not committed) produces a signed APK that apksigner verify accepts.
  4. No secret values appear in workflow files or logs. Signing steps don't echo env vars.
  5. The runbook names every secret and every manual step.

7. Worktrees, staging and blockers

Worktree checks before Wave 1

  • git status in the main worktree is clean and HEAD is the approved Wave 0 commit.
  • git worktree list shows no leftover worktrees from an earlier run. If two primary sessions run at the same time, each has its own worktree created from the same base commit, and neither touches the other's paths.
  • Launch all eight Wave 1 agents in one message, each with isolation: "worktree", so they start together.

Bringing work back

  • The primary session copies only the paths listed for that task, for example rsync -a <worktree>/app/src/main/java/io/reddevs/tidemark/explorer/ app/src/main/java/io/reddevs/tidemark/explorer/. Anything the agent wrote outside its paths is reported back, not copied.
  • Remove each worktree after its copy is verified.

Staging (primary session only)

On 2026-11-19 the user authorized the primary session to commit and push whenever it judges the work ready. Release tags (T-011) still need the user's go-ahead, because a tag publishes a release.

  • Run git status first. Stage explicit paths only. Never git add -A, git add . or git commit -a.
  • Wave 0 commit: the T-001 paths from the dispatch table, PRIVACY.md, PRIVACY.fr.md, .gitattributes, memory-bank/ (journal files listed by name or the directory as an explicit path), and .agent/plans/tidemark-v1-implementation.html if the user wants plans in the repo.
  • Wave 1: one commit per workstream, staging that workstream's owned paths, so git log maps to task IDs.
  • No AI attribution lines in commit messages.

Blockers

  • Contract change needed: the agent stops that part, keeps working on the rest, and reports the exact diff. The primary session decides, edits the frozen file in the main worktree, records a decision in the Memory Bank, and copies the updated file into every live worktree.
  • Dependency missing or incompatible (connect-testing version, Vico API, AGP): the agent reports the error output and what it tried. The primary session changes the version catalog. No workstream edits gradle/libs.versions.toml on its own.
  • A test that needs a real device is replaced by a checklist item in section 6 and reported.
  • Blockers are recorded as issue events in the Memory Bank with the task ID.
